This milestone implements containerised deployment for the project: a shared Docker image for the API and worker, a Docker Compose stack (API, worker, MongoDB and a data-only BusyBox), and a CI workflow that builds and publishes the image to GitHub Container Registry. It also includes a Compose-based smoke test that verifies basic API flows and can be skipped when Docker is unavailable.

## Containerized services
- FastAPI serves the API (`viaje-ya-api`) on port 8000, while the worker reuses the same image to run `python -m app.worker` in the background.
- MongoDB (7.0) as the datastore and is paired with a BusyBox data-holder so the shared volume lives outside the database container.
- The root [`compose.yaml`](../compose.yaml) codifies dependencies, health checks, ports, and volume wiring for the full stack.

## Docker image decisions
- Built the shared image from `python:3.12-slim`, adding only `curl` to project requirements 
- sources in  `/app/src` so API and worker share one artefact with port 8000 exposed by default.
- Service-specific commands are set in Compose, letting the image stay generic.

## Data and configuration management
- The `mongo-storage` volume is owned by the BusyBox container and mounted by MongoDB, for the data-only requirement.
- Application containers receive `MONGODB_URI` and `MONGODB_DB` so they talk to the Compose-managed database instantly.
- Health checks gate startup for both the API and MongoDB, ensuring dependencies become ready before use.

## Continuous delivery to GHCR (GitHub Container Registry)
- The [`container.yml`](../.github/workflows/container.yml) workflow logs into GHCR, builds the image on pushes and PRs, and runs the Compose smoke test.
- Successful push events publish [`ghcr.io/arg0n4ut/viaje-ya-app:latest`](https://ghcr.io/arg0n4ut/viaje-ya-app:latest), keeping the registry in sync with main.

## Automated Compose test
- [`src/tests/test_compose.py`](../src/tests/test_compose.py) boots the stack, exercises  flows, and tears everything down.
- The `compose` mark and `SKIP_DOCKER_TESTS` flag let standard pytest runs skip the scenario when Docker is unavailable.
